# MVP 优化说明：实例定位、固定分析任务与本体浏览

## 本次实现范围

保留现有本体设计和 SQL 编译器，以增量模块实现三个优化点：明确实体属性命中；增强属性/关系解释与可执行边界；将固定料差分析注册为参数化任务。新增可点击的本体浏览页面。

运行时本体来自本项目内 `ontology-v1/`，不是项目同级的设计副本。没有修改那份外部本体。逻辑本体仍有 10 类实体、13 条关系；当前编译器支持其中 7 类实体、6 条关系。本次没有把剩余设计关系自动变成可执行 SQL。

## 1. 生产计划665如何命中

不是在 YAML 里存放所有生产计划，而是先识别类型和属性，再查询实例。例如“查生产计划ID 665的详细信息”，请求解析的预期输出是：

```json
{
  "route": "dynamic_query",
  "selector": {
    "entityType": "ProductionPlan",
    "property": "sourceId",
    "operator": "EQ",
    "value": 665
  },
  "threshold": null,
  "comparison": "GT",
  "limit": 100,
  "clarification": ""
}
```

| 字段 | 含义 |
| --- | --- |
| route | dynamic_query 为模型规划；analyze_material_gap 为注册料差任务；clarify 为需要澄清 |
| selector | 实例定位条件；全体有效计划计数时可为 null |
| entityType | 目标本体类型，目前实例解析支持 ProductionPlan |
| property | sourceId 主键、planNo 业务编号、name 名称 |
| operator | EQ 精确匹配；CONTAINS 仅用于用户明确要求的名称包含匹配 |
| value | 原问题的属性值，不允许从业务编号中抽数字猜主键 |
| threshold | 料差筛选阈值，0.05 表示5%，null 表示不筛选 |
| comparison | GT 严格大于；GTE 大于等于，供料差阈值使用 |
| limit | 最多返回行数，默认100，最多200 |
| clarification | 无法支持或缺少信息时的说明；正常为空 |

`request_router.py` 负责模型解析和契约校验；`entity_resolver.py` 根据白名单映射执行参数化检索：

```sql
SELECT id, code, name
FROM `mom-test`.`produce_plan`
WHERE deleted = 0 AND `id` = %(selector_value)s
LIMIT 21
```

这里 SQL 与值分开，参数为 `selector_value=665`。编号改查 `code`，名称改查 `name`。名称包含匹配会转义 `%`、`_`，防止它们变成非预期通配符。

唯一命中后返回 `sourceId=665` 和 `entityRef=mom:production-plan:665`；多条是 AMBIGUOUS，展示最多20个候选；零条是 NOT_FOUND。后两种都不继续规划/执行分析。界面点击候选会将明确 ID 写回问题，用户再次点击运行。此步骤仍需模型解析明确选择，不是自动执行查询。

`--execute` 未启用时不会连接数据库：ID可生成预览，但标记 UNVERIFIED；编号和名称则暂停，提示需要查库。没有查库时不会宣称已经找到真实实例。

定位 SQL 与分析 SQL 分开执行，因此不是跨两次查询的一致性快照。分析执行时会再校验计划 ID 是否存在。

## 2. 属性与关系如何表示

本体属性不是复制所有数据库字段。业务名由本体定义，数据库列由 `config/mapping.yaml` 映射，补充解释由 `config/property-semantics.yaml` 提供。

例如 `ProductionPlan.planNo → produce_plan.code`，`PlanBOMItem.parentId → produce_plan_bom_detail.parent_id`。后者指向 BOM 行主键，不是父物料 ID。`ProcessTask.outputProductId` 是工序产出物料，不是领用的投入物料。

浏览器展示的是三者合并的属性目录：

| 字段 | 含义 |
| --- | --- |
| id / label | 程序属性名 / 中文名称 |
| type / description | 数据类型 / 业务解释 |
| aliases | 用户可能使用的业务说法 |
| role | 普通属性 attribute 或关联键 relationship_key |
| unit | 单位是否已确认；未知数值单位标记待业务确认 |
| projectable | 当前编译器能否在最终结果中输出此属性 |
| resolvable | 能否用于实例定位；目前仅生产计划ID/编号/名称 |
| filterableInQueryIR | 能否直接写入当前 Query IR 的实体筛选条件 |
| physicalField | 实际映射字段，可能仅有设计映射 |
| executableMapping | 当前 MVP 是否已经登记该物理属性映射 |

“有属性”“有物理映射”“可以输出”“可以筛选”是不同能力，界面明确分开，避免模型把全部属性都当成可自由查询的条件。当前不是通用任意字段过滤器。

关系页展示起点、终点、基数、业务解释、实际执行映射和设计映射。简单关系如计划到工序任务按主外键连接；领料关系需要表头和明细两张表；质检/入库的设计中存在精确路径和回退路径，目前不能因为图中存在这条边就直接执行。

本次查询命中区另列 IR 显式引用的属性和物理字段。定位用到的名称/编号见定位页；JOIN键和指标内部依赖仍在编译轨迹中查看，避免把它们混称为用户直接命中的属性。

## 3. 普通问数与固定料差任务

普通问题仍由模型生成受约束的 Query IR，如生产计划详情只需要 Scan → Project → Limit，不强行增加 BOM 或领料。

固定料差分析先由模型识别任务和参数，`tasks.py` 再读取 `config/tasks.yaml` 注册的 `examples/query-ir-material-gap.json`，展开步骤。它是固定 Query IR 配方，不是模型临时生成一段 SQL；SQL 仍由统一编译器根据映射生成。

| 阶段 | 程序行为 |
| --- | --- |
| 定位 | 唯一确定生产计划ID |
| 关系遍历 | 计划 → 工序任务，以及计划BOM、领料、退料、报工分支 |
| 分支聚合 | 领料/退料按工序任务+物料聚合；报工按工序任务聚合 |
| 指标计算 | 按已登记公式计算额定产出、实际报工、差异和严重度 |
| 可选筛选 | 无阈值时不生成 Filter；有阈值时保留 GT/GTE 边界 |
| 输出 | 排序、投影、行数限制，再编译参数化SQL |

每个事实分支先聚合再关联，避免领料明细与报工明细直接多对多连接造成数量重复。

保持现有业务口径：额定产出=总领料量/标准单耗；实际报工=自检合格+自检不合格；差异=额定产出−实际报工；差异率=差异/额定产出；严重度=差异率绝对值。

退料量展示但不从总领料中扣除；损耗率字段暂不参与公式。因此这是当前已登记的投料差异口径，不等于净耗料分析。BOM目前处理工序产出节点的直接子项，未覆盖任意多层展开、替代料、非BOM领料或BOM多重匹配消歧。这些需要明确规则后再增加任务版本，不能靠模型猜测。

任务版本为 material-gap-v1。阈值未给出的一般分析不筛选；明确查询异常但未提供阈值时，提示模型采用大于等于5%。固定任务改善计划结构稳定性，但模型路由仍可能出错，仍需真实问句评测。

目前只是本地注册工具函数，没有部署 MCP 服务。以后可以给同一个函数加工具Schema或MCP包装，无需重写本体映射与执行器。

## 4. 模型分别输入输出什么

请求解析模型输入用户问题、生产计划属性、任务清单和请求契约，输出定位条件与任务参数。它不确认记录存在。

普通查询的规划模型输入可执行实体、属性、关系、指标依赖、算子解释、Query IR Schema、相关示例，以及程序已解析的计划 ID，输出本体语言 Query IR。程序强制沿用已解析 ID，并校验计划；不合法最多修复一次，保留首次 IR 和校验错误。

固定料差任务跳过规划模型，直接由程序展开 Query IR。两类查询都使用同一校验器和编译器。

可选结果解读模型输入用户问题、实际返回数据、查询参数、步骤和任务口径，输出自然语言回答。提示词限制它不把截断/筛选后的结果称为全量，不随意相加不同物料，不把未知单位或空值编造成确定值。模型回答失败不会丢失已查询结果。提示词并不构成所有数字都正确的数学保证，原始结果始终保留。

## 5. 如何操作界面与查看追踪

启动命令见 README。页面“本体浏览”中，点击关系图中的实体节点，右侧会显示属性、相关指标与任务、当前执行映射和设计映射。点击关系文字或连线，右侧会显示关系方向、基数、是否可执行、当前 JOIN 映射和设计映射，并可继续跳转到关系两端实体。图下方保留等价选择框，供图形较密或键盘操作时使用；当前不是拖拽式知识图谱编辑器。

点击本体仅查看本地元数据，不调用模型、不执行SQL。当前浏览页面没有修改本体或写数据库的入口。

一次查询后依次查看：实体定位与任务 → Query IR → 校验与映射 → SQL → 执行结果。JSON 的 request 是模型解析请求，resolution 是数据库实例定位证据，task 是注册任务，planning 是具体步骤和来源，compilation 是 SQL 与参数，execution 是真实数据库结果，answer 是可选模型回答。

自然语言示例：

```text
当前有多少有效生产计划
查询生产计划ID 665的详细信息
查询生产计划ID 665的BOM
查询生产计划ID 665下的工序任务
查询生产计划编号SCJH-202609011648090001的详细信息
查询名称包含MRP的生产计划的详细信息
分析生产计划ID 665的料差，不筛选阈值
分析生产计划ID 665的料差，筛选差异率超过5%的记录
```

这些是待模型在线回归的问句，不是对实际数据存在性的保证。
